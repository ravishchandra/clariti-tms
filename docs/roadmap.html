Phases

Five phases. Phase A is the lock; everything else is gated on it.

AValidate on your Flutter app

~1 week · the unblock

Goal: ClaritiTMS translates a real, shipped Flutter app from English to 2–3 locales, and the translated .arb files render correctly in the simulator.

If translation quality is bad on a real app, none of the other phases matter. If it's good, the recording becomes the hero demo video for everything downstream.

A1Add .arb parser to app/ingestion/parsers/1 dayTreat values as flat-JSON; use @key metadata as description context — this is what makes us smarter than Tolgee on Flutter.
A2Add .arb writer to app/publication/0.5 dayReverse of A1; preserve @key metadata in output.
A3Add flutter to PLATFORM_FORMATS5 mincli/main.py:27
A4Wire Flutter format detection into MCP ingest_strings30 minapp/mcp/tools.py
A5Fork your Flutter app to a clean branch30 minYou drive.

A9Write up as docs/14-flutter-case-study.md1–2 hrsReal numbers: # strings, MT cost, review time, % approved unchanged.

Definition of done: your Flutter app, in your simulator, with FR/ES/DE translations produced by ClaritiTMS, looks correct.

CPublish to PyPI

~1 hour · after A validates

Goal: pip install clariti-tms works for an external developer.

Metadata in pyproject.toml is mostly ready: name clariti-tms is free on PyPI (404 check), version 0.1.0, AGPL-3.0, entry points wired.

  • Add [project.urls] block (Homepage, Repository, Issues).
  • README audit for PyPI rendering — relative links to docs/ and marketing/ break.
  • Build + inspect: python -m build, unzip -l dist/*.whl — verify no .env, no test fixtures, no secrets ship.
  • TestPyPI dry run — catches metadata + entry-point bugs before they're permanent.
  • Real PyPI release with API token. Irreversible: can't delete, only yank.
  • Later: GH Actions trusted publishing (OIDC, no secret in CI).

DHosted trial path (monetization wedge)

~3–5 weeks · parallel stretch

Goal: a prospect tries ClaritiTMS in 60 seconds without spinning up Postgres + uvicorn locally.

AGPL keeps self-hosted free; managed tier is the revenue source. Without D, the marketing site's pricing tiers stay fake. Don't gate Product Hunt on D — a real "Managed (early access)" email form is enough for launch day.

End-state mental model

What this looks like 90 days from now.

  • AGPL OSS. Anyone can self-host for free. Mass adoption, transparent moat.
  • Managed tier (paid). Hosted version for teams who don't want to operate Postgres + uvicorn. AGPL pushes companies that need to embed it into commercial licensing.
  • Agent-first. The MCP server is the differentiator vs Lokalise. The pitch: "Cursor / Claude Code drives translation."
  • Developer-minded. CLI-first, JSON output, structured logs, AGPL — everything engineers respect.

The immediate next concrete action

Start Phase A1 — add the Flutter .arb parser.

Specifically:

  • Create app/ingestion/parsers/flutter_arb.py with parse_arb(content: str, filename: str) -> ParseResult
  • Plain string values become translatable keys; @key metadata dicts populate description (placeholders, descriptions) — this is the bit that makes ClaritiTMS smarter than Tolgee on Flutter
  • Register in app/ingestion/parsers/__init__.py:parse_file dispatcher
  • Add flutter-arb to FILE_FORMAT_EXTENSIONS in cli/main.py:34
  • Tests in tests/ingestion/test_flutter_arb_parser.py: plain strings, placeholders ({name}), ICU plurals, descriptions, @@locale directive

Then A2 (writer), A3–A4 (wire-up), then you bring the Flutter app and we run A5–A9 together.
